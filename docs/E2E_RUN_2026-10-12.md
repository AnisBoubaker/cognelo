# Grouping verification — 2026-10-12

This is a point-in-time verification record for the section grouping/team implementation based on commit `816f80d` plus the grouping changes. It does not claim that the full E2E suite completed without failures in one run.

## Results

- Unit/API tests: **1,085 passed in 243 files**, including 22 new grouping service cases and the new course-tab navigation case.
- Type checking: passed across all workspaces and scripts. The new grouping E2E spec also passed a separate strict TypeScript check because the root command does not include E2E specs.
- Lint: no errors; 47 existing warnings. New grouping files and the corrected preview assertion pass focused lint.
- Full E2E run: **109 passed, 2 failed, 5 did not run** (serial-suite skips), out of 116 cases.
- Content/grouping/preview rerun: **10 passed, 1 failed, 2 did not run**. All four content cases and all five grouping cases passed; the remaining failure was the Parsons assertion below.
- After correcting that assertion, all **4 student-preview cases passed**. Every one of the 116 cases therefore has a successful execution across the full run and reruns.

Grouping coverage includes independent team assignments across groupings, persistence, pending enrollments, team identity across renames, student search, stale and concurrent saves, failed-draft recovery, guarded navigation, a 390-pixel viewport, section teacher/TA/student permissions, and enrollment/section deletion cascades. No grouping tests were skipped or relaxed.

## Failure analysis

### Nested text-content duplication: intermittent, unresolved

Expected: after a teacher duplicates visible nested text content, the learner can see both the original and copied titles inside the expanded folder.

Observed: `content-resources.spec.ts:67` could see the original but not the copied title. The teacher-side copy assertion had already passed. This same assertion also failed intermittently before the grouping changes. It passed unchanged on the isolated content-suite rerun; that does not establish that the underlying issue is fixed. Three later serial content cases were skipped in the full run and passed during the rerun. Product code for text duplication was not changed.

### Parsons preview: incorrect test wording, corrected

The initial blocks are shuffled. The UI reports either a correct answer or that blocks are **out of order**. The test accepted `correct|misplaced`, so it passed only when the initial order happened to be correct. Failure screenshots showed valid “out of order” feedback. The assertion now accepts `correct|out of order`; the ordinary preview API and non-persistence assertions remain. No Parsons product behavior changed.
