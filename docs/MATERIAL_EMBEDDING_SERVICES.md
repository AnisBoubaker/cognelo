# Prepared material embedding services

Material plugins own extraction and embedding preparation/refresh through `ServerContentTypePlugin.indexing`. Consumers call core's `getMaterialIndexStatus` and `prepareMaterialIndex`; core resolves the authorized resource and dispatches to its owning plugin. The plugin supplies its source revision/freshness policy and invokes a core-provided `store` callback after extracting teaching content. No consumer imports another plugin.

Material extraction, embedding preparation and indexed-text previews must not use Playwright, Puppeteer or another browser-rendering fallback, or execute website JavaScript. This is an explicit user requirement. Read public HTTP responses and supported source files through the bounded plugin services; report unsupported script-only content and use a readable text/PDF alternative instead. Previews read saved indexed text without fetching or rendering the website. This restriction concerns the material pipeline, not the separate automated browser test suite or unrelated application features.

The core store uses the configured embedding model, bounded 2000-character chunks with overlap, and batches of 16 inputs. OpenAI `text-embedding-3-small`/1536 remains the compatibility default; other configured models use their native dimensions (up to 8192). Responses must contain finite Float32-safe vectors of consistent dimensions. The question-generation model is excluded from embedding compatibility. Compatible identical text reuses shared vector records. Changed material produces an immutable index; snapshots retain exact index IDs. Ordinary resource metadata and learner responses contain no extracted source corpus, vectors, or credentials.

Vectors are stored as Float32 bytes in PostgreSQL and searched with bounded exact cosine similarity (at most 10,000 reference chunks and 20 million float values per search context; 2,000 chunks per resource). This first delivery does not require changing the PostgreSQL image or installing pgvector. The service boundary permits a later approximate/vector-database implementation. Content indexes are course-scoped and access-checked; shared vector records contain hashes and numeric vectors only. Per-resource leases with heartbeats prevent simultaneous rebuilds; cancellation may leave reusable vectors but cannot publish an incomplete index.

## Owning plugin extraction

- Text: the saved Markdown body.
- File: bounded textual/code files, source/text entries inside ZIPs, and text-based PDFs. PDFs use Poppler `pdftotext` with bounded input/output/time and private temporary files. Install `poppler-utils` on Ubuntu, or Poppler through the local package manager. Empty, scanned, encrypted or unextractable PDFs fail explicitly; OCR is not performed.
- Link: public HTML, Markdown/plain text and linked PDFs. Reveal.js inline template Markdown and same-origin `data-markdown` files are included without executing JavaScript. The page must expose its teaching text statically. Private internal link summaries are not an indexing source.
- GitHub: dedicated GitHub repository materials with public root URLs, default-branch content pinned to one commit. Includes common source/text formats and authored build definitions. Skips symlinks, submodules, IDE metadata (`.idea`/`.vscode`/`.vs`), generated CMake/build output, dependency/cache directories and macOS sidecars before applying the limits of 200 files, 512 KB each, 4 MB total. Authored XML/YAML and `.github/workflows` are still eligible. No checkout or source execution occurs. Public GitHub API rate-limit errors fail visibly and can be retried. The versioned `teaching-source-v2` extraction policy refreshes old readiness while preserving existing pinned snapshots.

External fetches validate and pin public DNS addresses, reject credentials/private addresses, bound redirects, time, downloaded and decompressed sizes, and never send application cookies. ZIP preparation reads stored/deflated entries only in memory: at most 25 MB compressed, 1000 directory entries, 200 selected text files, 512 KB per text file and 4 MB total text. Validate paths, local/central headers, sizes and CRC; reject symlinks/encryption and cap actual decompression. UTF-8 and BOM-marked UTF-16 text are supported. Executables, nested archives, hidden/macOS metadata and generated/dependency folders are skipped; archives without readable text fail explicitly. Each retained file has its own path/provenance.

Teacher solution files are independent private activity records and are never automatically embedded as course materials.

Embedding consumers use the [core reference-material capability and UI](ACTIVITY_MATERIAL_REFERENCES.md), including explicit hidden-resource selection (unchecked by default). A prepared snapshot records the hidden index subset and preparing manager; background generation uses that manager’s current authorization only for the selected private subset and preserves learner authorization for other indexes. Core’s generic visibility checks remain unchanged. Retrieved private text is model context, not a student resource/preview permission or a learner payload. See the [homework reference](../packages/plugin-activities/plugin-coding-homework-grader/docs/REFERENCE.md#hidden-reference-materials).

## Inspecting indexed teaching content

Course managers can inspect saved indexed passages through the generic core `getMaterialIndexPreview` service. It authorizes the course/resource, restricts the query to the caller-supplied candidate index IDs in that same course/resource, and returns at most ten exact passages per page. Its explicit projection contains text/title/position and index identity/date only: no numeric vectors, private metadata, connection credentials or model requests. Students and section-only staff have no authoring-preview access.

The core Reference materials panel exposes **Preview indexed text** beside indexed material. For a prepared selection it resolves the pinned snapshot and shows that exact reference version, even when another homework has created a newer index for the material. Otherwise it shows the latest index for the saved embedding selection. Paging retains the selected index identity and rejects a changed selection; failed/late/closed reads cannot overwrite the active preview. The UI explains that indexing alone does not prove complete pedagogical coverage, and presents source strings as plain text rather than executing/rendering embedded HTML.

The Link plugin rejects recognizable page shells and missing required slide sources before calling core storage. Its extraction policy version requires older link indexes to be revalidated before new submission opening; active immutable snapshots remain stable. Static content hidden in lesson panels/slides is retained. These checks do not render arbitrary JavaScript applications or establish semantic completeness; use a public PDF/text alternative or upload material when extraction is unavailable, and inspect the saved content for coverage.

GitHub owns `embeddingFreshnessHours`: default 48, configurable from 1 to 8760 per repository in material settings. Freshness measures the last successful check, even when unchanged vectors were reused. Other material types become stale when their saved source changes; a teacher can request an explicit forced refresh through core. Homework checks freshness before enabling submissions and then uses its pinned prepared snapshot. Student generation never refreshes reference materials.

## Model configuration and retained work

The teacher chooses an embedding-capable connection/model in **Course settings → AI → Course embedding model**, shared by all embedding consumers in that course. Activity reference panels link to that setting and own only their material selection/preparation. One connection credential can serve both model purposes. OpenAI-compatible connections (including Codex) use `/embeddings`; Ollama uses `/api/embed`. Claude is generation-only. See [AI connections](AI_MODEL_CONNECTIONS.md).

`ContentMaterialIndex.embeddingConfig` records the model, dimensions option, connection, owner consent and endpoint fingerprint without any secret. Legacy empty configurations resolve to `text-embedding-3-small`/1536. Cache keys normalize Codex to the OpenAI protocol so compatible existing indexes remain reusable. Prepared descriptors include actual vector dimensions so homework rejects an oversized selection before enabling submissions. Query vectors always use the prepared model configuration, including historical catalogue names; disabled connections, changed endpoints, revoked owners or incompatible vector dimensions fail explicitly. Homework snapshots retain the chosen connection independently of the index's original credential, allowing compatible indexes to be reused without depending on another teacher's private token.

The course setting and generic activity-reference routes, snapshot locks, migration and compatibility rules are documented in [shared activity references](ACTIVITY_MATERIAL_REFERENCES.md). Material plugin extraction/refresh ownership is unchanged.
