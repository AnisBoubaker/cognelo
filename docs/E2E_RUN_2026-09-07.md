# Playwright E2E run — 2026-09-07

## Scope and environment

This run exercised the repository's 33 Playwright tests against the real local web app, API, PostgreSQL database, and configured plugin services. The suite used one worker, seeded admin/teacher/student credentials through the shared authentication fixtures, uniquely named disposable course data, and Google Chrome at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` because the pinned Playwright Chromium was not locally available.

The covered paths include authentication, global and course-scoped authorization, administration, course/group/participant/bank management, all installed activity authoring and learner flows, compound Tests, attempt policy, automatic grading, grade release, and student grade visibility.

## Test and fixture corrections made during execution

- Aligned category and heading expectations with actual accessible names and scoped repeated controls to their owning regions.
- Used semantic selection throughout ordinary forms and a Monaco-model helper for code editors whose EditContext integration cannot be reliably populated with Playwright `fill()`.
- Provisioned and cleaned plugin-private activity data through real lifecycle routes, including exact restoration of the intentionally disabled placeholder plugin state.
- Replaced timing-sensitive assumptions with response or visible-state checks and bounded dynamic polling.
- Kept the attempt-limit assertion unchanged while marking it as an expected failure linked to issue #160.

## Follow-up policy

Future E2E product failures are report-only unless a task explicitly asks for implementation: retain evidence, document expected and observed behavior, create or link a GitHub issue, and do not alter application code. Test-code or fixture errors may still be corrected so the intended user flow can run.
