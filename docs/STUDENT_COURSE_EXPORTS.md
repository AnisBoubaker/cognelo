# Student course exports

Course managers enable **Allow students to export course content** in Course → Settings → General, then use the existing Save course action. The setting defaults to off, including for existing courses. Learners see **Export course content** in their section workspace only while it is enabled. This is separate from the teacher's [submitted-answer exports](ANSWER_EXPORTS.md).

The download is a ZIP containing a rights-of-use PDF first (`000`), a contents PDF (`001`), PDFs arranged in the visible course folders, and original uploaded course files alongside those PDFs. Top-level content numbering starts at `002` to prevent collisions with the reserved documents. Numbered paths preserve sibling order and disambiguate duplicate names; unsafe filename characters are replaced and UTF-8 components are bounded. Empty visible folders are retained. Learners enrolled in several currently accessible sections receive a separate top-level folder for each section. The archive is generated for the signed-in learner; there is no student selector or public download URL.

## Usage rights and confidentiality

Administrators configure **Settings → Course exports** (`/settings/course-exports`) with a site-wide plain-text usage-rights field and **Allow teachers to edit usage rights**. Both use the shared Save/Cancel and unsaved-change guard. Site terms initially are empty and teacher editing defaults on. The authenticated policy GET exposes only terms and the edit permission; only an administrator may write it.

Enabling course export reveals **Usage rights** and **Watermark PDFs with “Confidential”** in the course's General settings. Courses initially inherit site terms. When editing is allowed, a course manager may customize the text or choose **Use site default**, which stores `null` inheritance. When editing is disabled, the field is read-only and site terms apply to every course, overriding retained course-specific terms. Unlocking restores those saved course terms. The server rejects stale/forged term edits with `COURSE_EXPORT_RIGHTS_LOCKED`; the administrator lock and course-term writes serialize under one transaction-scoped policy lock. A stale form reloads the lock and retains its saved course terms instead of presenting a failed draft as persisted. The independent watermark remains editable. Disabling course export retains both choices.

The separate first PDF is named `000-Rights of use.pdf`, `000-Droits d’utilisation.pdf`, `000-使用权.pdf` or `000-حقوق الاستخدام.pdf`, using the course Subject's teaching language rather than the requesting interface locale. It identifies the course and downloading student and includes the effective usage terms verbatim. User-authored terms are plain text, escaped, whitespace-preserved and never automatically translated. Empty terms receive a localized notice that no additional terms were specified; the built-in copyright statement still applies.

Every page of every generated PDF—including the rights document, contents, activity attempts and appended assignment artwork—includes the course-language equivalent of **“This copyrighted material was downloaded with appropriate usage rights by STUDENT NAME. All rights reserved to the copyright owners.”** Student identity comes from the authenticated account. Repeated footers reserve page space and escape names; appended PDF artwork is fitted above an embedded Unicode-capable footer so multilingual notices do not depend on PDF standard-font character coverage.

The optional watermark uses the literal **Confidential**, faintly and diagonally, on every generated page, including appended assignment pages. Original uploaded files copied into the ZIP, including original PDFs and PDFs inside original ZIPs, remain byte-for-byte unchanged and are exempt from stamping. Terms, the edit policy, course choices and teaching language are part of the final export revalidation: a change during generation discards the archive.

## Included content

- Text materials: their saved Markdown, including tables, bounded math and available images.
- Link materials: the public title, URL and description. URLs remain clickable and appear as printed text.
- GitHub materials: the normalized repository URL. Exporting does not clone a repository or fetch linked pages.
- File materials: original bytes in their original format, plus a PDF identifying the file. Existing uploaded PDFs and ZIPs stay intact.
- Activities: the accessible prompt and each submitted/graded attempt in the assignment's current assessment mode, with the learner's own saved answer and permitted recorded feedback. Started drafts and deleted attempts are excluded.
- Compound Tests: public introductory instructions before submission; submitted question membership/order and prompts come from the saved manifest and revision, with the corresponding saved child answers. Exporting never starts a Test to reveal its questions.
- Programming Homework: public preparation instructions, the original assignment PDF plus one appended copy as inert page artwork, original provided files through the existing bounded download service, and accessible submitted source/text and challenge answers. Multiple provided files retain their logical folders inside a ZIP; a sole original provided ZIP stays unchanged. Binary student hand-ins are identified in the PDF rather than executed or converted.

Standalone prompts use current authored content, as the learner's normal review does; compound Test revisions retain their historical content. Current gradebook totals and comments are labelled separately from individual attempt scores. A missing or unauthorized image receives a visible placeholder. A plugin without an explicit student export handler contributes only its public description and an unavailable-content notice; teacher export handlers are never a fallback.

## Access and feedback

The server requires an actual student enrollment even for an account that also has teacher or administrator roles. It resolves only published, currently available sections belonging to that enrollment, forces learner visibility through folder ancestry and section overrides, and applies effective section/team/student assignment exceptions. Unassigned or inaccessible activities, inactive plugins and resources outside that scope are excluded.

The shared activity-content closure rule applies to exports. When a teacher hides prompts and answers after attempts end, those prompts, saved answers, attachments and feedback are excluded. Only an already released current total may remain as a grade-only receipt. Safe Exam Browser requirements are checked with the authenticated, activity-scoped server cookie; staff rights do not bypass them. Deferred Homework may retain its public preparation prompt/files while its protected question/answer stage remains unavailable.

Summative scores and feedback require released grades and no pending grading review. Ordinary Formative exports saved answers and public deterministic test outcomes without AI feedback; Formative with automatic AI feedback may include available human-facing saved feedback. MCQ answer keys, reference solutions, hidden test inputs/outputs and diagnostic messages, private grading instructions, raw provider/model artifacts, internal link summaries and derived embedding indexes never enter the student projection. Student code is escaped and never executed.

Immediately before delivery, the server checks plugin-private projections again and reloads enrollment, course opt-in, visibility, effective policies, release/review state, attempt revisions and authentication validity. Changed access/content discards the prepared archive. These reads never initialize attempts, submit work, execute graders, call AI, update grades or mark content/messages read. Cancellation aborts preparation and image work, closes the print browser and suppresses late client downloads.

## Contracts and rendering

`POST /api/courses/:courseId/student-export` accepts only `StudentCourseExportRequestSchema` (`locale`: `en`, `fr`, `zh` or `ar`). Actor, participant, group, attempt identities, usage terms, teaching language and watermark choices are resolved server-side; extra selection/rights fields are rejected. Authorization precedes the 4 KiB bounded JSON reader. Success returns a private `no-store` ZIP attachment with a UTF-8 filename. Disabled/unavailable access returns 403, changed content 409, excessive size/time 413 and occupied renderer slots 429. No archive is persisted.

`GET /api/settings/course-exports` requires authentication and returns `{ usageRights, allowTeacherEditing }`. Administrator-only `PUT` accepts that exact shape, with a 100 KB bounded body and 20,000-character terms limit. It updates only its own singleton columns and the administrator identity, preserving timezone/name policies. Course `PATCH` accepts optional `studentCourseExportUsageRights: string | null` and `studentCourseExportConfidential: boolean` alongside the existing enablement flag; missing fields preserve existing choices, and normal course-management authorization/audit applies.

Activity plugins opt in through `ServerActivityPlugin.studentExport` with an explicit `activityTypeKeys` allowlist. The input contains the authorized activity and either `attempt: null` for a public prompt or one exact own submitted attempt, plus grading/AI-feedback permissions and an abort signal. The plugin owns private persistence and must return a safe projection without evaluating answers. Content plugins opt in through `ServerContentTypePlugin.studentExport`, returning typed document blocks and optional original file bytes. The shared `ExportDocumentBlock` union supports Markdown, escaped code, tables and validated HTTP(S) links. Core does not import concrete plugins or query their tables.

The API reuses the [offline Chromium renderer and runtime installation](ANSWER_EXPORTS.md#runtime-installation). Uploaded images must also have an active reference belonging to the export's accessible material/activity or saved Test revision. Deferred public-preparation images require both a declared preparation field and the matching activity reference. Public raster fetches retain DNS-pinned public-address checks and shared byte/time budgets. Prompt PDF artwork is embedded into clean pages without copying document actions/scripts.

Limits are checked before or incrementally during preparation: 50 available sections, 2,000 content-tree items across the exported sections, 1,000 submitted attempts, 1,000 item PDFs, 32 MB of stored core payloads (counting repeated shared activity content across sections), 64 MB of projected text/attachments and 128 MB of archive contents/output. Archives allow at most 4,000 entries and 3,200-byte paths; name components allow 120 UTF-8 bytes. Ordinary uploaded files retain the 25 MiB file-plugin limit; Homework retains its frozen-file integrity and provided-file limits. Two shared per-process renderer slots cover preparation through printing, with a four-minute lifetime. Image budgets are shared with teacher exports: 100 unique sources, 20 MB of bytes, 30 seconds of image work, and 10 MB/five seconds per public fetch hop. Output is never silently truncated.

## Migration and verification

Core migration `202611250001_student_course_export` adds `Course.studentCourseExportEnabled BOOLEAN NOT NULL DEFAULT false`. The additive/idempotent `202611250002_student_export_usage_rights` adds `ApplicationSettings.exportUsageRights` (empty default), `allowCourseExportUsageRights` (true default), nullable `Course.studentCourseExportUsageRights` and default-false `studentCourseExportConfidential`. Apply `npm run db:migrate:all`, regenerate clients and restart the API/web through the normal upgrade workflow. Existing course enablement and unrelated application settings remain intact. No new environment variables, plugin tables or execution-runner changes are required. Reuse the existing API PDF browser/fonts installation; Judge0 and the Web Design runner do not create these PDFs.

Core tests cover enrollment and staff-role isolation, forced learner access, closed/released grades, SEB and deferred preparation, Test snapshots, current-mode history, inactive plugins, payload bounds, changed projections/access and cancellation. Plugin tests check withheld answer keys and private test diagnostics. Renderer tests check safe paths, original bytes, printable links, escaped answers, independent total/attempt grades and discarded output. `tests/e2e/student-course-export.spec.ts` exercises teacher opt-in/save/cancel, multiple-section and dual-role visibility, student downloads, nested/hidden content, original file integrity, feedback release, compound Test privacy, Homework frozen-source/assignment-page/original ZIP integrity and staged-feedback exclusion, read-only academic state, mobile bounds and cancellation using an isolated local database. Use Poppler to inspect actual generated PDF text and render representative pages for visual review.

`student-course-export-rights.spec.ts` verifies administrator and teacher Save/Cancel/reload, policy authorization, stale/direct locked-field rejection, retained overrides and inheritance reset, course-language rights filenames, original PDF integrity, copyright attribution and optional watermark on every generated page, unchanged academic records and mobile containment. Its site policy is restored during cleanup. Unit coverage also checks policy changes before delivery, escaped terms/names, PDF watermark operators and notice/page composition.
