# Programming Homework memory

- The display name is Programming Homework; French uses Devoir de programmation. Preserve the existing package/plugin/activity keys, routes, storage paths and database identifiers. Display-name migration only refreshes catalogue labels, never authored activity titles or academic records.
- The [approved workflow](../../../docs/CODING_HOMEWORK_SUBMISSION_WORKFLOW.md) is authoritative. Individual hand-in remains the default; opt-in [team delivery](../../../docs/TEAM_ACTIVITY_SUBMISSIONS.md) shares files/hand-in while preserving private individual answers and grades. Preparation manages uploads only, never browser code edits. A ZIP replaces the entire draft collection and retains its internal folders. Individual-file UI uploads use the root; destination-folder and folder-creation controls are intentionally absent.
- Drafts create no academic attempt. Revision checks and a per-student workflow lock serialize edits and final hand-in. Freeze copied, hash-verified files in one transaction; enqueue only when question activation permits, otherwise wait without resolving models/references. Only teacher cancellation/deletion permits another hand-in.
- Private teacher solutions belong to course/bank authoring owners. Same-course duplication retains all authored settings, explicit models and the source's effective material selection, cloning its active prepared snapshot while reusing immutable core index IDs. Keep final submissions disabled and student/assignment state excluded. Bank transfer/sync still clears course references and explicit models. Never expose private solution source through student projections or add it automatically to course embeddings. See [duplication](docs/REFERENCE.md#duplication-within-a-course).
- Teacher solution edits use owner locks and revision checks, ignore macOS ZIP metadata, and validate source text before JSON persistence. ZIP replaces the catalog; single-file replacement refreshes only that file’s functions. Removing a function excludes it from the catalog without changing its source file. Prune linked saved requirements atomically and reconcile the editor’s saved baseline while preserving unrelated draft edits. Reject changes while submissions are enabled.
- Provided-file authoring has a separate manager-only revisioned collection service for bank/course owners. Keep ZIP path/empty-folder metadata through downloads/copies; preserve unchanged attachment identities and exact bytes. Existing ZIPs are read without mutation and unpack only on edit. Share course hand-in/settings locks and bank owner locks with legacy upload/delete routes; failures/cancellation before commit preserve the collection. Never touch private solutions or frozen submissions. See [provided-file authoring](docs/REFERENCE.md#provided-file-authoring-collection).
- Validate C signatures without execution: name, argument types/count and return type; ignore parameter names/storage qualifiers and equivalent array parameters. Keep typedef spelling, pointer depth and pointee qualifiers. Academic gaps/syntax incompleteness require acknowledgement; archive, storage and analysis-resource limits block.
- Material plugins own extraction and index preparation/refresh services. Call them through core only. Homework owns selection and pinned snapshot IDs, never its own material vector store. Question-model changes do not invalidate embeddings. Repository freshness is checked at enablement, not per student.
- Course reference authoring is entirely core-owned through `usesMaterialEmbeddings` and the `materialReferences` persistence adapter. The adapter owns only private selection/snapshot/operational locks. Core supplies selection Save/Cancel, folder/search/status/preview/preparation UI and the course-wide embedding setting. Inside the top Activity tab, shared left navigation separates Activity, Teacher solution, Submission requirements, Question Generation, Submission settings and Simulation. Question controls use an On/Off switch; core stage activation/late settings use switches too. Only list selections and explicit acknowledgements use checkboxes. Concepts and core references remain top tabs. One main Save/Cancel and navigation guard covers every left-section field, including model/concurrency; do not add nested save bars or autosave switches. Keep core references and explicit uploads independent. Teacher solution is a filename/signature master-detail picker with first-file selection; manual requirements/import belong in Submission requirements. Preserve drafts on incidental refreshes and mount progress outside hidden panels. Bank authoring omits course-specific panels. See [shared reference services](../../../docs/ACTIVITY_MATERIAL_REFERENCES.md).
- Explicit model choices go through core access checks. Freeze the question model/reference snapshot when generation is admitted (at hand-in if active, otherwise later teacher activation) and embedding model with the reference snapshot; never include tokens. Existing jobs keep their model when the teacher changes the next-submission choice. Legacy generation and required-function selection also honor explicit homework generation overrides; all supported text providers are permitted. See [AI connections](../../../docs/AI_MODEL_CONNECTIONS.md).
- Homework E2E model fixtures use disposable course owners and private connections, never temporary shared-account defaults. A hand-in freezes whichever authorized connection resolves at that instant; restoring preferences later cannot fix a captured mock model. Verify stored model identity and question/function/file ownership separately when diagnosing generic fixture text. See [test isolation](../../../tests/e2e/README.md#ai-fixture-isolation).
- Material selection locks while Questions answering is active; static requirements lock while file hand-in is enabled or frozen hand-ins exist. Course embedding changes leave enabled homework on its pinned model; disabled activities must prepare with the current course choice before opening. Generate a new prepared selection after selection changes, reusing unchanged compatible vectors. Existing frozen submissions retain their snapshot and generation settings.
- Reference previews read the exact prepared snapshot's index IDs through core, falling back to the current-model material index only outside that prepared selection. Require course management, validate resource/index/page scope, expose only saved text, and never invoke models or leak vectors/metadata. Preview paging is read-only, abortable, localized and source HTML is displayed literally. A newer index from another homework must not replace the pinned preview.
- The durable queue defaults to 2, caps the entire homework queue at 4, and supports teacher changes for waiting jobs. The student status panel shows a spinner and polled queue position while queued, then generation status without a queue number while running. Do not suggest leaving the page; background persistence remains unchanged. Hide the spinner on terminal failure/readiness and respect reduced-motion preferences. Heartbeats/retries recover interruption; complete questions publish atomically under the workflow lock after verifying job ownership. Cancelled requests retain provider slots until the worker unwinds. Legacy analysis/generation entry points must not mutate version-2 submissions.
- `assessmentFlow: deferred` separates preparation from answer timing. Tag preparation/prepared-file/hand-in with `submissionStageId: files` and answering/challenge-answers with `questions`; core owns each stage's SEB requirement. Declare `supportsSafeExamBrowser: false` on files so local uploads always stay outside SEB; questions remain configurable. Core rejects unsupported flags, including overrides. Legacy global SEB protects answering only. Resource receipts and read-only frozen work remain preparation-exempt. Use shared stage access gates and the host launcher, never inspect SEB proof in the plugin. The verified Answer action creates/resumes the core attempt. Never disclose ready questions through the preparation projection. Preserve existing starts for historical/continued attempts.
- Saves and completion lock the plugin submission and core attempt. After the authoritative deadline, discard incoming answer content and submit saved answers including blanks. Durable deadline jobs and the generic timed-finalization hook use the same path and recheck effective exceptions.
- Teacher cancellation retains old files/questions/answers and audit evidence, withdraws its associated grade, grants one replacement after released grades, and invalidates queued/running work. Keep grade-release state for the rest of the class. Details-page management includes work still queued without core attempts.
- Course managers author/open submissions. Grading and cancellation use scoped course/section staff capabilities. Student APIs expose safe states/counts and generic failures, never private diagnostics, model prompts, retrieval provenance, raw model output or stored names.
- Generated Prisma clients are ignored local build artifacts. Do not recommit them: they embed machine paths and native binaries. Keep schemas/manifest migrations tracked and run normal database generation commands.
- Student view is inspection-only; never create and delete academic submissions to emulate preview. Submitted-work exports and historical review use retained files and questions without regenerating or executing them.
- Use shared Markdown, action icons, dialogs, application timezone and content-closure contracts. Autosaves preserve answers across reloads. Preparation/material actions are cancellable; student background question generation deliberately has no Cancel action.

See [reference](docs/REFERENCE.md) for routes/persistence and [historical decisions](docs/DECISIONS.md) for the retained legacy pipeline. Track current work in the [progress record](../../../docs/CODING_HOMEWORK_IMPLEMENTATION_PROGRESS.md).

- Teacher workflow errors must go through `useNotifications` as well as the inline state, including save/model/refresh and reference preparation failures. Name the failing material and mark its row; retain successful indexes for retry. Cancellation is not an error notification. Keep the operation owned until the post-action refresh settles, and never overwrite unsaved model choices after a failed/cancelled action. ZIP extraction belongs to the file material plugin through core.
- Student workspace operation/load failures use shared notifications/history only, without a duplicate page-top banner. Structural check results and persistent workflow/file-viewer states remain in their relevant panels. Both answering views confirm manual finalization with an immutable-answer warning and a numbered list of blanks (whitespace counts as unanswered); Cancel preserves drafts. Some/all blanks are valid final answers. Close confirmation on completion/timeout; deadline finalization must never await a student decision. Preserve locking, exact retry semantics and saved-answer-only expiry.

- At hand-in, resolve and freeze the course Subject’s teaching language in `questionLanguage`; never let the submitted/session `locale` choose question language. Older queued work resolves it from the course. Promote private generation instructions to the system prompt in both prepared and legacy generation, with the fixed language/JSON/privacy contract intact. Question Generation exposes the existing `generationInstructions` field through the same activity draft/save guard.
- Question context is an allowlisted snapshot of submitted code, filename, function name, language and truncation status. Existing questions may resolve their retained function/file only when both belong to the question’s submission. Cap excerpts at 24,000 characters (the model evidence bound), retain the full read-only file viewer, and never project ASTs, storage paths, teacher prompts or retrieval examples. Questions/context remain behind the Answer/SEB gate.
- Current and legacy student answering share `HomeworkChallengeQuestion`: a numbered card with the prompt before code, a labelled answer field, and visible separation between questions. Use shared Markdown/code rendering. Container width determines side-by-side versus stacked code/answer layout; code scrolling stays within a keyboard-focusable frame. Presentation changes must preserve answer IDs, autosave, timeout disabling and completed-state protection.
- Teacher Review and grade uses the shared wide (1840 px) workspace; its embedded panel must fill that workspace so the toolbar cannot float beside a narrower default dialog. Questions/answers open first, files use the shared left-tab viewer, and grading sits beside the content on wide screens. Fetch file text on demand through `gradebook-file`, scoped to the grading staff's group, participant, exact submission and stored path; never eagerly include all source or reuse a learner's latest-file endpoint. The shared viewer aborts stale reads and resets per selected submission. Report grade/feedback dirtiness to the host's close/student/attempt guards and confirm before changing the attempt filter. Keep historical/formative review read-only and unsupported regrade actions absent.

- Portaled generation-instruction controls share the activity saved baseline and stay hidden until authoring data loads. Capture the textarea value before scheduling a functional state update; reading the event target inside the updater can lose portaled edits. Render authoring progress in the document body so Left-section saves remain visibly blocking when Activity is hidden.

- Prepared and submitted files use shared `SideNavigation`/settings layout, not a plugin-specific tab style. Open the first file automatically; preserve selection through workspace polling and reset it for a new submission. Keep code read-only and horizontally contained, including on mobile. Abort and ignore stale reads on tab changes/unmount, clear old content immediately, and give failures a retry plus notification. Filenames appear only in the left tabs; no repeated heading or file size above the aligned content pane. Draft revisions trigger a fresh selected-file read, including same-path replacements. Tab delete crosses are sibling buttons, never nested interactive controls, and require confirmation; they disappear after hand-in.

- Snapshot native FileList entries before awaiting replacement confirmation; clearing the file input mutates its live FileList. Keep File objects in the operation so confirmed same-path/ZIP replacements upload the chosen bytes.

- Student checks are explicit UI actions backed by fresh preparation validation. Do not reveal the requirements list before Check my submission. Gate Submit on the checked current revision/result and, for academic gaps, a fresh incomplete-work acknowledgement; invalidate both after changes. Explain structural-only scope and confirm immutability before hand-in. Server-side validation at hand-in remains authoritative.
- Student resources are two conditional downloads, never a raw attachment list. Provided-file ZIPs must select only the authorized owner’s `provided_file` attachments, exclude private solutions/requirements/PDF statement data, stream bounded chunks, validate file sizes/hashes, and preserve all duplicates under safe unique names. A sole provided ZIP passes through unchanged. Keep `activity-file` PDF previews inline unless `download=1` explicitly requests attachment disposition.

- Bulk draft removal is one revision-checked metadata transaction under the existing workflow lock. Clear files and folders together, reject frozen/stale submissions, then remove only the obsolete draft bytes after commit. Both per-file and bulk cancellation preserve the previous structural check; confirmed changes invalidate it.

- Challenge difficulty tests understanding, not obscure knowledge or endurance. Target one code-grounded point with a complete answer in 2–3 sentences, reasonable for the student who wrote it at this course level. Vary concrete valid/boundary inputs, conditions/guards and other local choices; avoid long traces, unrelated subquestions, missing context, traps, or treating buggy/undefined behavior as a correct deterministic result. Teacher focus instructions remain authoritative within this short, fair scope. Both generators receive previous questions for diversity. This is generation guidance, not a sentence-count restriction on saved student answers.

- Exclude unchanged provided C functions before candidate limits/ranking. Compare only activity `provided_file` attachments (including C/H inside ZIPs), never the private teacher solution or course references. Use literal-preserving token hashes, ignoring whitespace/comments and source path; AST similarity masks literals and is unsuitable for equality. Hand-in pins a compact hash/name manifest under the settings lock, shared with provided-file mutations. No provided file bytes are copied per student; parsing is cached per attachment version. Older queued/legacy records acquire a baseline once. Never fall back to generating from unchanged starter code when no eligible function remains; expose the localized no-eligible-code state and require teacher review. Existing questions remain unchanged. Details and limits are in the [reference](docs/REFERENCE.md#excluding-unchanged-provided-code).
- A provided helper's name is not itself an invalid question: asking about the student's guard/call/result handling is legitimate. Keep target exclusion deterministic, remove all modified submitted function names from the excluded-name list, and accept helper references when the question first anchors itself in the eligible target. Correction retries retain code/references/language and explain the specific rejection. After three invalid outputs, stop that job with a private question number/reason; do not automatically repeat the same failed question set. Transient provider failures retain ordinary queue retries.

- Team delivery uses core `supportsTeamwork`/`teamwork` contracts, section grouping policies and current membership tokens. Store one Workspace/frozen `team_source`, with independent member/final records referencing the same physical source bytes. Never trust a submitted team ID. Draft writes require the workspace/member context key plus revision; Answer requires the expected current submission ID. Grouping locks serialize membership with file mutations, answering and question publication.
- Common questions generate once and copy safe question/context rows to current members; separate mode queues one set per activated member and does not compare across students. Pending enrollments receive their own participation on activation/access. A stable activity owner holds the shared source record so deleting the original submitter cannot cascade other members’ files.
- Team moves revoke private bindings and core attempts/grades. Minimal file/membership audit events retain actor/path/hash/revision; empty workspaces erase private rows and queue idempotent physical cleanup. Reset retains shared code and reuses the common set or generates a new individual set. Stale cancellations cannot cancel a newer hand-in. Submitted ZIP downloads preserve folders and stream verified stored bytes; structural rechecks use frozen requirements.

- If a team activity disallows individual submission, unteamed learners may only consult/download assignment resources. Do not create a private draft/member binding or show preparation/check/submit controls. Resolve current membership under the grouping lock before granting workspace access, including stale uploads and file reads. The safe workspace status remains readable so the page can show a localized team-required notice and refresh after joining/leaving.

- File hand-in timing is separate from challenge-answer timing. Core submission-stage scheduling now owns deadlines, durations and late policy. The plugin configuration service supplies legacy `settings.submissionPolicy` as read-through defaults only; new legacy-endpoint writes delegate to core. Explicit core null values clear legacy defaults. Shared activity Settings owns editing/timezone/inheritance. Check the server clock under the settings lock before validation and before freezing. Persist `submissionTiming` with accepted time, deadline, late flag and exact `lateByMs`; display elapsed delay without recalculating from current policy or answer completion. Shared children, late joiners and challenge resets inherit the frozen timing. No implicit grade penalty or availability extension.

- Finite cutoff recovery is server-owned: learner workspace reads and staff Class overview (`manage-submissions?recoverAutomatic=1`) freeze eligible nonempty drafts through the same hand-in locks/queue. Editor list reads do not trigger it. Active file submission and live enrollment/team ownership remain required; references are required only when generation is admitted; staff may recover saved files after learner activity closure without extending access. Never accept a browser-supplied automatic flag. Stop file mutations at the cutoff, acknowledge academic gaps automatically, retain explicit automatic provenance, and keep hard safety/integrity failures blocking. Use cutoff time for lateness, actual recovery time for audit; respect cancellation at/after cutoff and reject post-cutoff-modified/backdated drafts. Verification is not submission: show the yellow reminder with dark, readable text and the separate automatic-cutoff explanation.

- The reference picker includes hidden course material, including hidden-folder descendants, but defaults only to visible resources before the actual activity placement. Explicit folder selection includes hidden descendants; saved selections survive reload. Prepared snapshots record `hiddenReferenceIndexIds` and `preparedByUserId`. Only that subset uses a currently authorized preparing manager for private core search; visible/legacy references retain learner authorization. Never loosen generic student resource visibility or expose retrieved private text. Same-course copying sets the copying manager as preparer while reusing pinned indexes.
- Restart the development API after changing background generation handlers: process-global job registrations may retain the earlier function despite route hot reload. A fresh API process is required to test the actual updated worker.

- Teacher Simulation is course-only and uses a checked ZIP plus saved settings/references with the same `generatePreparedHomeworkQuestions` routine as the real worker. Require its same-teacher/activity preflight ID, expiry/hash/requirements checks and explicit incomplete acknowledgement. Never fall back to the private solution. Temporary teacher preflights are separate from student final submissions; create no core attempt/grade or course index for simulation. Results are transient and expose only question/solution-code context; use course teaching language and unchanged-provided-code exclusion. Reject unsaved/stale inputs, propagate AbortSignal to the AI transport, and ignore cancelled/late responses.

- `settings.questionGenerationEnabled` defaults to true; preserve an omitted older-client value. Reject changes with active hand-ins and close the manual submission gate on an accepted mode change. File-only hand-in freezes policy/count0 and files, completes core attempts atomically via the trusted deferred-completion service, and creates no AI/deadline jobs. Late team members receive independent completed attempts; revoke old attempts before creating new ones. Preserve hidden settings/references and disable challenge reset for file-only records. PDF preview starts collapsed; source preview and student-management panels are absent from authoring.

- Course authoring accepts a separate optional, partial `workflow` patch for model/concurrency/opening; legacy deadline writes delegate to core. Legacy workflow endpoints stay compatible. See [save boundaries](docs/REFERENCE.md#routes-and-persistence).

- Declare `files` and `questions` stages with localized names; only files is active in file-only mode. Core resolves current policy/exception precedence and caps all stages at overall Until. Persist `preparationStartedAt` once per draft/shared workspace when the file stage is active (including activation of a prepared draft), clear only on teacher reopening, and include it in finite-cutoff recovery. Queue waiting never starts answering. The additive clock migration is part of the normal plugin migration path. See [stage contract](../../../docs/ACTIVITY_SUBMISSION_STAGES.md).

- Teacher authoring explanations use shared `HelpLabel`/`HelpTooltip` after their title or label on the same row. Preserve native field names, descriptions, unsaved drafts and existing notifications.
