# Homework rubric grading

## Plugin independence

Programming Homework and Programming Exercises are independent plugins. Homework owns its grading and execution implementation. Useful exercise code may be copied into this plugin and maintained independently, but must not create cross-plugin imports, runtime dependencies or a common grading/execution module shared between the two plugins.

## Authoring

Course and bank authoring offer **Activity / Concepts / Grading**, with the course Reference materials tab unchanged. Grading uses shared left navigation for **Rubric / Tests** and the same activity Save/Cancel draft as Activity and Concepts. Existing homework keeps manual grading until **Use rubric grading** is enabled.

The code rubric evaluates the entire project once, independently of functions. A separate generic question rubric applies to every submitted challenge answer, with equal averaging across questions. Each rubric has stable criterion IDs, titles, descriptions, positive integer criterion weights totaling 100, and independent AI grading directions. Component points also total 100; either rubric may contribute zero. Turning off questions sets their points to zero and code points to 100 while retaining the question rubric. Test points are fixed at zero in this delivery. Test generation, per-required-function weights, reference validation and execution are expressly deferred.

Generate rubric opens a guidance dialog, then cancellable shared progress. Confirmation saves only the chosen rubric's guidance privately; criteria remain unsaved until ordinary Save. Cancellation/failure preserves the rubric; confirmed guidance survives. Guidance writes are ordered before retries and late/cancelled responses cannot change the draft. Generation receives the assignment text, optional PDF text, private solution, complete curriculum catalog/live selected targets and course Subject language. The code rubric remains project-wide; the question rubric must fit any individualized question and a focused answer of roughly 2–3 sentences. It never generates a per-function rubric.

Private authoring lives under assignment `settings.grading`; `settings.gradingRubricGuidance` is independently merged for generation preferences and protected against stale activity saves. `settings.gradingBatchInstructions` stores the shared batch dialog's optional run guidance. Course/bank copy and synchronization preserve these reusable fields through the existing assignment-settings lifecycle. None are student configuration.

## Teacher grading

**Assess with AI** and **Review and grade** use the platform feedback, guided-batch, audit and grade-release services. Summative submission does not run AI. The course assessment-feedback connection/switch is required for AI; ordinary manual rubric assessment requires no model. Questions continue to use the independently selected generation model.

AI applies current saved rubrics and directions, plus any run-specific directions and reviewed examples. Teacher policy is in the system prompt; source and answers are untrusted evidence. The source is assessed as a whole project, and answers against their specific question and retained submitted-code context. An underlying mistake is deducted once under its most relevant criterion. Empty answers receive zero and the Subject-language no-answer message without a model call. Nonempty incorrect or incomplete attempts receive normal assessment. Structured criterion identities/scores/comments are validated, with one bounded correction retry. No grading path executes code or invents test outcomes.

Every deducted criterion's **Feedback / Rétroaction** must explain each reason for lost points and include all supporting examples from the submitted work, rather than only representative examples. Code feedback cites actual filenames/functions and short exact excerpts; missing code is described as absent instead of inventing an excerpt or line number. Answer feedback uses the actual answer and its retained code context, without deducting for code defects the student correctly explains. Evidence stays entirely in the existing criterion feedback text, with no prescribed format or additional fields. Summaries remain brief and the no-answer rule still applies. Prompt version `homework-rubric-v2` records this policy; existing reviews change only through a new assessment or teacher edit.

Criterion feedback accepts up to 50,000 characters consistently in AI-output validation, teacher edits and the review form, with a 16,000-token output allowance per assessed rubric. Feedback is stored as strings in existing PostgreSQL JSONB rubric/grade snapshots; the review's general feedback column is already TEXT. Neither requires a migration. Long comments are retained without truncation; ordinary request-size and export budgets still apply. No structured evidence schema is introduced.

AI source evidence is capped at 160,000 bytes of C/H files, the private solution at 200,000 serialized characters and assignment text/PDF at 100,000 characters. Larger work remains manually gradeable; evidence is never silently truncated. PDF extraction uses the existing bounded Poppler utility. Feedback and rubrics use the Subject teaching language, independently of viewer locale.

Reviews show lazy, exact-submission file previews, the individual questions/answers, editable criterion scores/comments, narrative feedback, live code/question contributions and the host final-grade override. Narrative-only saves retain grades. Unscored criteria remain null, distinct from zero. A complete component may produce an explicitly partial grade; any missing contributing component blocks release. An explicit individual final-grade override is complete. Historical and formative inspection remain read-only; activities without rubric grading retain their manual review screen.

## Teams and concurrency

Team code-rubric feedback belongs to the exact frozen shared source; question feedback stays on the individual attempt. New reviews reuse compatible shared code scores. Publishing a code score updates existing teammates' code component and recomposes their grades through core in the same transaction. Individual answers, question scores and explicit final-grade overrides are retained. Ungraded members see the shared component on opening their own review; they still require their individual weighted components. Cancelled/deleted hand-ins, replaced workspaces and old memberships are excluded.

The plugin's `sharedGrading` service publishes only its private shared component and projects current related attempt IDs. Core independently validates same-course/activity/section, latest summative submission and grader scope, then writes ordinary audited changes. Core never queries homework tables. Shared component revisions reject stale competing rubric edits. Feedback and rubric-grade saves share one transaction; a shared-component conflict rolls back both. A final-grade override remains an independent teacher action.

AI runs stage immutable `PluginCodingHomeworkReview` artifacts using metadata status `staged`. Normal history, exports and manual-grade fallbacks exclude them. Keep/success promotes only exact activity/attempt/artifact identities through the neutral host transaction. Discard/cancellation never changes shared scores. Batch publication first revalidates and records all prepared individuals, then synchronizes shared components; internal propagation cannot invalidate another prepared teammate's optimistic snapshot. Reviewed examples are bounded, omit learner/account identities from model evidence and retain individual question ownership. A same-source reviewed example keeps its shared code scores.

Private review artifacts retain policy, effective directions, examples' attempt references, model response, language and prompt version. These remain server-side. Shared source metadata retains only the common rubric score, its policy hash and revision. Private-prefixed feedback fields are removed from learner grade projections. No database migration or new environment variable is required: this delivery uses existing private assignment, submission and review JSON storage.

## Released student results

The existing release and content-closure gates apply. Results show the weighted code/question contributions, criterion scores and explanations, individual questions/answers and final teacher grade. Zero-weight components are omitted. The plugin rechecks learner, section, active released grade and exact submitted attempt before projecting questions. A final-grade override resolves its latest submitted attempt. Private solutions, instructions, hashes, retrieval metadata, model artifacts and test internals are excluded. Teacher answer exports include the latest reviewed code/question criteria and component scores through a bounded, read-only block projection; staged artifacts never appear. Learner copy describes grading/feedback without identifying its mechanism.

The current scope remains rubric-only grading. Executable tests, including generation, per-required-function weights and private-solution validation, remain deferred.
