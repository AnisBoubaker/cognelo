# Programming Exercises Memory

Read [docs/DECISIONS.md](docs/DECISIONS.md) only for the area being changed.

- Public activity config is student-visible. Reference solutions, full templates, hidden tests, rubrics, and raw evaluation artifacts must remain private.
- Judge0 is server-only and all source/input/output fields cross its boundary as Base64. Status 13 is an infrastructure failure, never a learner result or consumed attempt.
- Judge0 endpoint, auth header/token, enablement, and per-process/thread flag are admin-managed core runner settings. Plugins must resolve the service through core rather than read runner environment variables; core currently selects the first enabled runner and preserves the boundary for later round-robin pools.
- Bank/course private rows require copy, sync, duplication, and deletion hooks. Reusable bank Tests must invoke those hooks per independently owned child rather than referencing a source bank activity. Duplication must copy the complete private configuration; generated reference solutions must merge rather than erase rubrics.
- Bank variation runs only after that independent private copy and preserves exact concept, skill, and misconception selections. It generates a title and description aligned with the new prompt, regenerates the reference/template and exact original visible/hidden test counts, preserves hidden-test weights, and revalidates against Judge0. Recheck both counts immediately before persistence. Every test correction prompt must retain the complete prompt/reference/template context. If a generated solution/template cannot support the required cases, variation regenerates that pair and retries tests once. The copied rubric/config remains unchanged and independently editable; never regenerate it as part of variation.
- Enabled hidden tests must pass the private reference solution before save. Persist per-test validation fingerprints, reuse only matching passing results, and rerun new, execution-relevant changed, or previously failing tests; reference solution, language, time limit, or private template changes invalidate every test. The signed preflight receipt prevents the persistence request from executing the same dirty tests again. `{{ STUDENT_CODE }}` is required; `{{ TEST_CODE }}` is the optional per-test harness insertion point.
- AI test generation warns before replacing existing tests, then asks for 1–15 visible and 1–15 hidden tests, defaulting to 3 and 8. Generated tests always use unordered `contains_lines`, so every expected output must contain a non-empty line and callable harnesses must print that result instead of relying only on assertions. Reject malformed generated output in the AI correction loop before Judge0. Names are descriptive, outcome-oriented, and at most 50 characters; hidden tests may cover the same case type as visible tests with different values to expose hard-coded solutions.
- Standalone drafts use core `ActivityResponseDraft`; embedded Test drafts use `TestItemAttempt`. Do not mix those persistence paths.
- Every successful standalone submission uses a mode-tagged core attempt. Only summative attempts consume attempt limits or enter grading; unclassified legacy plugin submissions remain inspectable but do not consume a summative attempt. Practice-run grouping is derived from timestamps around submissions.
- Judge0 output is compared before truncation. Bound new execution/validation diagnostics when saving and bound legacy rows again when serializing them, or one runaway run can stall every later history view. Learner execution text must also wrap unbroken lines inside shrinkable containers so output cannot widen the editor/test workspace.
- Rubrics are general teacher grading tools, not conditional on model feedback. Summative model grading is teacher-triggered; formative feedback may run immediately.
- Whole-activity AI grading uses the shared guided-batch contract. Candidates must already be graded and contain criterion explanations plus at least one narrative comment; at most three may be selected, selected examples are excluded from reassessment, and learner identity is never included in the model payload. The run uses the dialog instructions whether or not the default-on setting update is kept; persistence updates only the current course activity's private instructions once before the batch.
- Teacher review and AI-grading routes consume core course capabilities: explicit course teachers/admins work course-wide, while section teachers/TAs are restricted to their assigned groups. Hidden-test mutation, authoring, release, and persisted activity-wide AI-instruction changes remain course-management operations.
- Original executions and submission-time snapshots remain immutable. Teacher test regrades append private test-evaluation records; teacher-triggered feedback uses the current rubric and latest successful test run, whereas formative/Test-child evaluation retains the submission snapshot. Final grade recomposition uses current component weights and core audited regrade flows; a missing rubric score never counts as zero.
- With rubric grading enabled, a deterministic tests-only score is a partial grade until rubric evidence exists or a teacher records a final override. The plugin reports current component completeness to the gradebook; partial and submitted-ungraded rows block release, while true non-submissions do not.
- Gradebook **Review and grade** combines the submitted code, latest test evidence, rubric scores, Summary/Strengths/Improvements, and the host final-grade override. It shows the automatic-tests and rubric contributions against their configured proportions plus their live calculated total. Its confirmed clear-content action empties only learner-facing narrative and criterion explanations in the unsaved draft; it preserves rubric/test scores and the final grade. Rubric edits recompose first; an explicitly changed or previously teacher-set final grade is then recorded as a separate teacher override. Released final grades and generated or teacher-authored feedback can be challenged; the course Challenges tab mounts this same dialog in place. Challenged feedback remains editable because core retains the immutable artifact/snapshot and challenged hash while linking every teacher revision and grade change to append-only audit/research events.
- Gradebook **Class overview** combines the private reference solution and hidden-test aggregates with the configured rubric. Each rubric criterion remains visible when ungraded. Aggregation prefers current gradebook feedback so teacher-authored and revised summative scores win, then falls back to the matching attempt's completed evaluation for formative work that has no grade.
- The released learner grading report is plugin-owned and release-gated. It includes all active submitted/graded code attempts and their latest saved test evaluations, sanitized teacher comments/rubric explanations, conditional automatic-test/rubric contributions, and the final total; it must not expose hidden inputs, expected outputs, private rubric instructions, reference solutions, or raw model artifacts.
- Rubric and learner feedback generation use the Subject teaching language, not the viewer locale.
- New course and bank exercises, including local Test children, inherit the optional single-language Subject default selected from the configured Judge0 runtimes. Missing and multiple-language Subject values deliberately create an exercise with no language; saving, generation, validation, and execution are blocked until the author chooses one. Existing and copied exercises retain their saved language.
- Monaco assets are first-party for SEB compatibility, with the controlled plain-text fallback retained.
- The student template projection drops whitespace-only hidden boundaries. Monaco cursor and selection limits must be derived from the current model rather than the previous React value so empty answers accept their first keystroke and select-all clears only student code.
- Monaco/basic code editors, rendered code, and Markdown code spans/fences inherit the shared non-translation policy; never extend that opt-out to the surrounding instructional prose.
