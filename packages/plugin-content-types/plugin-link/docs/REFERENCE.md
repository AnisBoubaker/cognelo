# Link content reference

The shared manifest registers `link` with the link icon, shell creation, external-URL embedding source, `link-content-settings`, and `link-content-presentation`. The application composition root registers its shared/server manifests; the frontend composition registry registers its settings form and presentation resolver.

Resource `title` stores link text (1–180 trimmed characters). Metadata stores `url` (absolute HTTP(S), at most 4,000 characters, no username/password), `description` (optional plain text, at most 2,000 trimmed characters), and `openInNewTab` (boolean, default true). The browser form and server enforce validation; query strings and fragments survive normalization. HTML entered in a description remains text.

Shell creation without a URL stores `setupStatus: "draft"`; its presentation has no href and its server open action is `none`. Saving a valid URL clears the draft status. Partial updates preserve omitted fields; clearing description or setting `openInNewTab` to false is supported. Invalid updates do not mutate the resource. Duplicate retains supported public source fields plus an independent copy of the private settings under the new resource identity.

The optional SDK row-presentation key resolves safe `{ href, target, description }` data through the frontend registry. Teacher course rows, section staff rows, student content, and teacher Student view use it for both title and open-icon navigation. Target is `_blank` by default and `_self` when unchecked; new-tab anchors use `noopener noreferrer`. The server `resolveOpenAction` returns the same URL and target. All authorization and effective folder/section visibility checks remain in the existing content-resource services.

Embedding hooks expose the validated URL and a bounded external-reference document containing title, description, and URL. These embedding hooks do not crawl the target website and never include the internal summary. Explicit summary generation has its own bounded fetch path.

## Internal summary and AI generation

`PluginLinkContentSettings` stores `resourceId`, `internalSummary` (up to 20,000 characters), `maxWords` (1–2,000, default 100), `followSameDomainLinks` (boolean, default false), and timestamps. Its resource foreign key cascades deletion. Public create/update payloads may carry teacher-authored `internalSummary`, `summaryMaxWords`, and `summaryFollowSameDomainLinks`, but the handler excludes them from metadata and persists them through `afterPersist` in the same transaction as the generic resource row. Duplication copies the private row through the same hook. Learner resource listings, open actions, and embedding documents remain public-only.

`GET /courses/:courseId/content-resources/:resourceId/summary` returns private settings only after course-management authorization. `POST` at the same path accepts the current unsaved URL, optional `maxWords` (default 100), and `followSameDomainLinks` (default false), then returns an unsaved `{ summary, wordCount, maxWords }` draft. When following links is enabled it also returns `sources: { includedPages, unavailablePages, omittedPages, shortened }` for the UI’s source report. The group-scoped generic dispatcher supports the same plugin route. Students and section-only staff cannot use these management endpoints. Generation never saves the summary; failures leave the current editor text intact.

The fetcher accepts HTTP(S), rejects credentials and non-public IPv4/IPv6 targets, validates every resolved address and redirect, and pins the selected address for the actual connection. It sends no browser cookies or authorization headers. A single 10-second budget covers DNS and HTTP, at most three redirects are followed, and both downloaded and decompressed content are capped at 2 MiB. Only final HTTP 200 responses with supported HTML/plain-text content continue; empty, oversized, unsupported, unreachable, and non-200 pages never reach AI. HTML extraction excludes scripts/styles and prefers article/main content, capped at 24,000 characters. PDF and authenticated/private-network content require a manual summary. These boundaries follow the [OWASP SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html) and use the [Node HTTP lookup option](https://nodejs.org/api/http.html#httprequesturl-options-callback) to pin the validated address.

Generation uses the teacher’s configured question-authoring AI agent. The course Subject’s `teachingLanguage` is read server-side and explicitly controls output, independent of viewer locale and page language. Page content is delimited as untrusted data; URL query strings are omitted from the model prompt. The model receives the word cap and a bounded output-token budget. Locale-aware `Intl.Segmenter` enforces the word cap on the response without a second AI call. Manual summary editing is limited by character count, not the generation word cap.

### One-level same-domain sources

The optional **Follow one level of same domain links** checkbox is unchecked by default and saved in the private settings row. The browser sends its current unsaved value with generation; toggling it alone never fetches a page. It does not affect the public link target or embedding hooks.

After the main URL passes its HTTP 200 check, the server parses HTML anchors, respects the first HTML `base` URL, resolves relative URLs against the final response URL, removes fragments, deduplicates destinations, and excludes the root URL. Only HTTP(S) links with the exact same hostname as the final main page are candidates; subdomains and lookalike suffixes are excluded. Anchor-only, credential-bearing, and non-web URLs are excluded. Plain-text sources have no discovered links. Redirects of linked pages must remain on that hostname, with every hop passing the usual public-address/DNS-pinning checks. This blocks off-domain redirects before any request to the new host.

At most **20 directly linked pages**, in document order, are fetched, with at most **three concurrent requests** and a **30-second total linked-page budget** (in addition to the main-page check). Each request retains its 10-second timeout, three-redirect limit, supported-content checks, and 2 MiB body/decompression limit. No child links are traversed. Redirects resolving to an already included page are deduplicated in the AI source set.

A failed main-page check aborts generation before AI. Unreadable/blocked/failed children are counted and skipped while retaining successful content. The UI reports included, unavailable, and omitted-page counts and whether source text was shortened; the 20-page limit is visible next to the checkbox. The main page plus every successful unique child is supplied in one AI request, with each page’s text and URL (without query/fragment) delimited separately. The prompt requests one combined summary in the course language and the existing total word limit. Combined extracted source text is capped at **200,000 characters**, divided equally across successful pages when needed; each page retains its original 24,000-character extraction limit.

## Migration and verification

Migration `202610200001_link_internal_summary` creates the private table idempotently through the content-plugin manifest. Migration `202610200003_link_summary_follow_links` adds the private boolean column with a default of false; existing summaries and word limits remain intact. `scripts/apply-plugin-migrations.ts`, called by `npm run db:migrate:all`, applies both activity and content-type manifests. Fresh plugin activation also executes its table-creation manifest; already activated installations need the combined migration command on upgrade. No core Prisma model owns the private summary. Declared plugin tables participate in the existing backup/deactivate/restore lifecycle.

Unit tests cover URL/status gating, public-address classification, redirect and size/time bounds, pinned connections, readable text extraction, zero AI calls on failure, course-language prompts, default/custom word caps, and private persistence hooks. Browser tests use mocked generation responses with real API/database persistence to cover editable drafts, defaults, error preservation, student denial, private-data exclusion, duplication, and cascading deletion. One-level tests cover relative/base URLs, exact-domain filtering, fragment deduplication, off-domain redirects, recursion prevention, concurrent/page/time/text limits, partial failures, default-off behavior, combined course-language prompting, saved true/false preferences, and duplicate independence.

## Shared action controls

Teacher, learner, and settings actions follow the platform [button and icon contract](../../../../docs/ACTION_BUTTONS.md). Use explicit semantic `ActionIcon` names with localized labels; dimensions and interaction colors are shared CSS, while tabs, disclosure rows, and specialized editor controls retain their own layout.
